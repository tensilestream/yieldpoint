    A volume-discount bug. The tiers are documented as inclusive — spend 500 or more, get 10% — but the comparison is strict, so an order landing exactly on a boundary is quietly undercharged. One test catches it, and that test is red.

    cart.py — the bug

    """Order totals with volume discounts.

The bug in here is the kind that survives review: the discount tiers are
documented as inclusive ("spend 500 or more") but the comparison is strict, so
an order landing exactly on a boundary silently gets the lower tier.
"""

from decimal import Decimal

#: (threshold, rate). Spending *at or above* a threshold earns its rate.
TIERS = (
    (Decimal("500.00"), Decimal("0.10")),
    (Decimal("100.00"), Decimal("0.05")),
)


def subtotal(items: list[tuple[Decimal, int]]) -> Decimal:
    """Sum of price x quantity."""
    return sum((price * quantity for price, quantity in items), Decimal("0.00"))


def discount_rate(amount: Decimal) -> Decimal:
    """The rate earned by spending ``amount``."""
    for threshold, rate in TIERS:
        if amount > threshold:      # BUG: should be >=, the tiers are inclusive
            return rate
    return Decimal("0.00")


def total(items: list[tuple[Decimal, int]]) -> Decimal:
    """Subtotal less the volume discount, to the cent."""
    gross = subtotal(items)
    net = gross * (Decimal("1.00") - discount_rate(gross))
    return net.quantize(Decimal("0.01"))

    tests/test_cart.py — the test that catches it

    from decimal import Decimal

from cart import discount_rate, subtotal, total


def test_subtotal_multiplies_price_by_quantity():
    assert subtotal([(Decimal("25.00"), 4)]) == Decimal("100.00")


def test_an_order_on_the_tier_boundary_earns_that_tier():
    """Spending exactly 500 earns the 10% tier: the tiers are inclusive."""
    assert discount_rate(Decimal("500.00")) == Decimal("0.10")
    assert total([(Decimal("250.00"), 2)]) == Decimal("450.00")


def test_an_order_below_every_tier_pays_full_price():
    assert total([(Decimal("10.00"), 2)]) == Decimal("20.00")

    Adding it

    three steps

    Three steps, and nothing in your agent loop changes.

    1. Install

    pip install yieldpoint

    2. Say which files hold the contract

    {
  "version": "1.0",
  "project": { "name": "Example Cart", "languages": ["python"] },
  "test_contract": {
    "protected_patterns": ["**/tests/**", "**/test_*.py"],
    "assertion_monotonicity": "block",
    "forbid_vacuous_assertions": "block",
    "forbid_new_skip_markers": "block",
    "forbid_swallowed_exceptions": "block"
  }
}

    3. Put it where edits pass through

    As a pre-commit hook:

    - repo: local
  hooks:
    - id: yieldpoint
      entry: yieldpoint review --staged
      language: system
      pass_filenames: false

    Or in an agent loop, where it can answer before the edit lands:

    from yieldpoint.verify import verify_change

verdict = verify_change(before, after, path, policy)
if not verdict:                      # falsey unless something was verified and clean
    return verdict.prescription      # hand this back to the model as the next turn

    That verify_change call makes no model call, opens no socket, and returns in under a millisecond on a typical file.
